# Anstoss mobile — end-to-end UX & design audit

Date: 2026-09-11 · Branch: `develop` · Method: full-source audit of the mobile
app measured against the Appllama app-design bar (native fidelity, navigation
grammar, anti-slop, motion, state cycles), plus the API surface behind each
screen. Simulator verification status is recorded in §6.

---

## 0. Verdict

The token layer is good. The screens do not use it well. Anstoss today reads as
a **club noticeboard** — a vertical stack of same-weight bordered cards — when a
player opens it. It should read as **the player's own week**.

Three structural problems explain most of the "this feels cheap" reaction:

1. **No hierarchy.** Home renders 5 bordered 16-radius cards in a row, each with
   the same border, same padding, same visual weight. When everything is a card,
   nothing is the answer.
2. **No identity.** Nothing on home says *you*. No name, no avatar, no number,
   no position, no season. A player cannot tell their home screen from a
   teammate's.
3. **Decisions cost a round trip.** The one thing a player does in this app —
   reply to events — is possible on exactly one card. Everything else is
   row → detail screen → reply → back.

## 4. What is being changed in this pass

**Slice 1 — Home rebuilt as "your week", not a noticeboard.**
Identity bar · one decisive Next-up hero with inline RSVP · a reply queue that
clears every outstanding answer without leaving home · a Spieler+ season strip
(attendance streak, MOTM, team form — all from live endpoints) · team pulse ·
full state cycle (skeleton / empty / error / refresh).

**Slice 2 — Events tab made answerable.**
Inline RSVP on every row · "Needs your reply" section pinned first with a count ·
one-accent RSVP control with selection haptics · controls collapsed to one row.

**Slice 3 — App-wide hygiene.**
Emoji icons removed across 7 screens · accent discipline · an icon-map
integrity test so a bad glyph name fails the build instead of rendering tofu.

**Slice 4 — Auth and onboarding.**
"Get started" and "Log in" landed on an identically worded screen; they now
carry intent. The sign-in CTA moved out of the scroll flow into a footer pinned
above the keyboard. Disabled buttons were a solid mid-grey slab that read as
broken; fixed at the `Button` primitive so every screen benefits. The
post-signup screen showed three filled green **completed** checkmarks against a
list of things the user had not done; now numbered. Logging out had the same
width and weight as the primary action; now a quiet text link. Club search was
a void with one grey line; now autofocused, illustrated, with an invite-code
escape hatch for the many clubs not in the directory.

**Slice 5 — Role homes and shared chrome.**
Identity hoisted from the player home to the route, so every role sees who they
are and which team they are acting in. `WizardStep` carried two stacked opacity
reductions on already-muted text tokens (contrast) and a `fontWeight: '800'`
that DM Sans does not ship; 18 such weights across 8 files normalised. Coach
home de-rainbowed, its duplicate roster pill removed, and its robotic
"COACH NEXT ACTION" chrome replaced. Payment status bars deliberately keep
green/amber/red: overdue money is a real semantic state, unlike availability.

**Bug found and fixed while doing it.** `activeTeamAccess?.team.displayName`
stops the optional chain one level too early. A membership carrying access
without an embedded team object crashed the entire home screen into the error
boundary. Fixed in 7 files.

## 5. Deliberately not done in this pass

- **TanStack Query.** The skill's default state architecture, but the repo has
  an established focus-refetch hook pattern (`useStreaks`) and matching it beat
  introducing a new data layer mid-revamp. `usePlayerHome` follows that pattern
  with request-sequence guarding and parallel waves. Worth revisiting as its
  own slice.
- **`expo-symbols` on iOS.** `Icon` is a clean one-file swap point and SF
  Symbols would be the cheapest remaining native-fidelity win, but it needs a
  native rebuild and a name audit across ~230 map entries.
- **FlashList.** 14 list surfaces still on `FlatList`/`SectionList`.
- **Coach / Admin / Parent home structure.** They now share the identity row and
  the corrected colour and copy rules, but their card-stack bodies have not been
  reorganised around a single decisive surface the way the player home was.
- **Dark mode.** Fully built and switched off by `userInterfaceStyle: "light"`
  in `app.json`. Flipping it is one line, but every screen needs a dark pass
  first, so it was left as the owner's call.
- **Appllama reference library.** The design methodology skill was followed
  throughout. The Appllama MCP server, which holds the real reference screens
  and assets, is not connected in this environment, so no screens were studied
  from it.

## 6. Verification status

- TypeScript: clean.
- ESLint (incl. the repo's raw-spacing-literal rule): clean.
- Jest: 127 suites / 618 tests passing, including the rewritten player-home
  behaviour specs, the 6-locale parity guard, and the new icon-map integrity
  test.
- iOS simulator: **blocked in this environment**, not by the app code. The
  installed dev client was stale (`ExpoDevice` missing), and rebuilding hits a
  toolchain failure: Xcode 26.6 links the *Release* React-Core prebuilt
  artifact into a Debug build, so dev-only symbols (`RCTPackagerConnection`,
  `RCTReconnectingWebSocket`, `facebook::react::Sealable`) are undefined at
  link time. Building RN core from source (`RCT_USE_PREBUILT_RNCORE=0`) is the
  workaround; `ios/Podfile.lock` and the pbxproj change when you do, so revert
  those before committing.
